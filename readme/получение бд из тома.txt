Файлы из именованного тома `mssql_data` нельзя просто скопировать «наружу» привычным способом, потому что они находятся внутри виртуальной файловой системы Docker. Однако есть два проверенных способа, как это сделать.

### 📂 Способ 1: Прямое копирование файлов (как они есть)

Этот метод подходит, если вы хотите сохранить физические файлы базы данных (`.mdf`, `.ldf`) или просто сделать «сырую» копию всего каталога.

**1. Узнайте физический путь тома на хосте**
Выполните команду:
```bash
docker volume inspect mssql_data
```
В JSON-выводе найдите поле `Mountpoint`. Обычно оно выглядит так: `/var/lib/docker/volumes/mssql_data/_data`.

**2. Скопируйте файлы из этого каталога**
Теперь, когда вы знаете путь, вы можете скопировать файлы напрямую, используя команды вашей ОС (cp, robocopy, scp и т.д.). Например, для Linux:
```bash
sudo cp -a /var/lib/docker/volumes/mssql_data/_data /путь/для/бэкапа/
```
Для Windows (через WSL2) путь будет отличаться, но принцип тот же — вы находите `Mountpoint` и работаете с ним как с обычной папкой.

**⚠️ Важное предупреждение:** Не пытайтесь читать или копировать эти файлы, пока контейнер с SQL Server запущен. Это может привести к повреждению базы данных. Остановите контейнер перед копированием: `docker stop <container_id>`.

### 📦 Способ 2: Правильный бэкап средствами SQL Server (рекомендуемый)

Этот способ считается «правильным» с точки зрения баз данных. Вы создаете `.bak` файл внутри контейнера, а затем просто забираете его оттуда одной командой.

**1. Создайте бэкап внутри контейнера**
Выполните команду `docker exec`, чтобы запустить `sqlcmd` и создать резервную копию базы данных в папке внутри контейнера (например, `/var/opt/mssql/backup/`). Сначала создайте эту папку внутри контейнера, если её нет.

```bash
# Создаем папку для бэкапов внутри контейнера
docker exec -it <container_id> mkdir -p /var/opt/mssql/backup

# Создаем бэкап базы данных (замените YourDatabaseName на имя вашей БД)
docker exec -it <container_id> /opt/mssql-tools18/bin/sqlcmd \
  -S localhost -U sa -P "SqlServerSuperPassword2017!" \
  -Q "BACKUP DATABASE [YourDatabaseName] TO DISK = N'/var/opt/mssql/backup/backup.bak' WITH NOFORMAT, NOINIT, NAME = 'YourDatabaseName-full', SKIP, NOREWIND, NOUNLOAD, STATS = 10"
```
*Примечание: В образе SQL Server 2022 путь к sqlcmd обычно `/opt/mssql-tools18/bin/sqlcmd`. Если у вас другая версия, путь может быть `/opt/mssql-tools/bin/sqlcmd`.*

**2. Скопируйте готовый `.bak` файл на хост**
Теперь у вас есть один файл, который можно легко вытащить:
```bash
docker cp <container_id>:/var/opt/mssql/backup/backup.bak ./backup.bak
```
Этот метод гарантирует целостность данных и является стандартным способом переноса или сохранения баз данных.

**Что выбрать?**
Если вам нужна просто копия «как есть» и вы готовы остановить контейнер — используйте **Способ 1**. Если вы хотите получить корректный, целостный бэкап, который можно потом восстановить — используйте **Способ 2**.
